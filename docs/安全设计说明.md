# 安全设计说明

本项目在基础功能之外，针对"移动应用开发及安全"课程要求做了以下安全加固，每一条都对应代码中的具体位置。

## 1. 权限最小化与动态申请

- `AndroidManifest.xml` 只声明了四个权限：`INTERNET`、`ACCESS_NETWORK_STATE`、`ACCESS_FINE_LOCATION`、`ACCESS_COARSE_LOCATION`，均为地图与定位的必需权限，不申请通讯录、短信、存储等与业务无关的敏感权限。
- 定位权限在 `PublishActivity` 与 `MapActivity` 中运行时动态申请（`ActivityCompat.requestPermissions`），用户拒绝时降级为"仅展示已发布物品位置"，不崩溃、不反复弹窗骚扰。
- `android:allowBackup="false"`，关闭 adb backup，避免数据库通过备份通道被导出。

## 2. 输入校验（InputValidator）

用户输入在入库前统一过一遍 `InputValidator`：

- 危险字符过滤：拦截 `<`、`>`、`'`、`"`、`;`、`--`、`/*` 等可用于脚本注入或 SQL 拼接的字符组合；
- 长度限制：标题 40 字以内，描述 200 字以内，联系方式 20 字以内，防止超长内容撑爆界面或数据库；
- 坐标区间校验：纬度必须在 [-90, 90]，经度必须在 [-180, 180]，拒绝非法坐标导致的定位异常；
- 空值校验：标题与描述不允许为空，避免产生无意义脏数据。

## 3. SQL 注入防护

`DBHelper` 中所有查询与写入均采用参数化方式：

- 写入使用 `ContentValues` + `insert()`，由框架完成转义；
- 查询使用 `selection` + `selectionArgs` 形式，例如
  `db.query(TABLE, null, "type = ?", new String[]{type}, null, null, "create_time DESC")`；
- 代码中不存在任何字符串拼接出的 SQL 语句，从根源上消除注入面。

## 4. 敏感信息处理

- 联系方式仅用于线下联系，不做公开展示，列表页不显示联系方式；
- 项目中不存储任何密码、Token 等凭据；地图 Key 只保留在 `AndroidManifest.xml` 的 meta-data 中，仓库内以 `your_amap_key` 占位，真实 Key 不提交；
- 数据库文件位于应用私有目录 `/data/data/com.example.lostfound/databases/`，其他应用无法直接读取。

## 5. 健壮性处理

- 地图与定位 SDK 的初始化、定位回调全部包在异常处理中，Key 未配置或网络异常时给出 Toast 提示而不是直接崩溃；
- `MapView` 完整实现 `onCreate/onResume/onPause/onSaveInstanceState/onDestroy` 生命周期代理，避免内存泄漏与黑屏；
- 点击标记的监听返回 `true`，避免地图默认行为覆盖自定义弹窗。

## 6. 后续可增强项

- 联系方式脱敏展示（中间四位打码）；
- 发布频率限制，防止刷屏；
- 图片上传前做类型与大小校验；
- 引入服务端账号体系后，改用 HTTPS + Token 鉴权。
